# NyaScraping

面向 MCU 的桌面调试工作台，使用 **Slint + Rust** 构建界面，以 **NyaScrapingCore** 作为调试后端，文本处理由项目内的 **Rust 原生文本后端**提供。

界面采用三栏布局：左侧为文件树与变量解析，中间为源码/波形展示，右侧为已添加的监视变量，顶部中央为调试工具栏。目前接通调试后端发现、安装、选择和卸载，以及源码读取和编译产物解析；段/节/符号报告与后端管理保留在中间标签页。已接通 GDB/MI 调试会话、运行控制、断点、调用栈、变量读取和定时实时显示；已接入 OpenOCD、pyOCD 和 probe-rs 无暂停波形与监视采集。

## 项目结构

```text
NyaScraping/
├── apps/desktop/                 # 桌面程序：组装依赖、工作线程、UI 模型映射
│   ├── src/                     # main.rs、presenter.rs
│   └── ui/                      # Slint 入口、主题、组件、功能页面
├── crates/
│   ├── domain/                  # 调试/工具/文本接口、会话状态、波形样本缓冲
│   ├── application/             # 命令、事件与用例；不依赖具体后端或 Slint
│   ├── debug-adapter/           # NyaScrapingCore 的 Rust 适配
│   ├── text-backend/            # 纯 Rust：文件读写、编码检测/转换、换行与安全保存
│   └── firmware-backend/        # 纯 Rust：编译产物、DWARF 函数/变量/类型与源码位置
├── backends/
│   └── NyaScrapingCore/         # Git 子模块，保持独立开发
├── docs/                        # 架构、界面与实施路线
├── examples/                    # 目标配置设计样例
└── .github/workflows/           # Rust/Slint/桥接与原生后端检查
```

详细设计见 [架构说明](docs/architecture.md) 和 [界面与实施路线](docs/roadmap.md)。

## 获取代码

```sh
git clone --recurse-submodules git@github.com:Thesummert/NyaScraping.git
cd NyaScraping
# 已克隆的仓库：
git submodule update --init --recursive
```

调试后端子模块使用 SSH 地址，提交由父仓库固定，不在构建过程中自动更新。

## 构建运行

需要 Rust stable（Slint 1.18.1 要求 Rust ≥ 1.92）及平台链接工具。Slint 与 slint-build 固定为相同版本。版本要求参考 [Slint 包清单](https://docs.rs/crate/slint/1.18.1/source/Cargo.toml)。文本后端使用纯 Rust 依赖，不需要 ICU、CXX 或 CMake 配置。

macOS：

```sh
brew install rustup
rustup-init
# 需已安装 Xcode Command Line Tools；已有 Rust 工具链可直接运行：
cargo run -p nya-scraping
```

Ubuntu / Debian：

```sh
sudo apt-get install build-essential pkg-config \
  libfontconfig1-dev libxkbcommon-dev libxkbcommon-x11-dev libxcb-shape0-dev libxcb-xfixes0-dev
# 安装 Rust stable 后：
cargo run -p nya-scraping
```

Windows 使用 Rust MSVC 工具链和 Visual Studio C++ Build Tools；本次尚未在 Windows 验证桌面程序构建。

## 打包发行文件

先按上文获取包含子模块的源码，并在目标操作系统上安装对应构建依赖。脚本使用当前 Rust 工具链的主机架构，以锁定的依赖执行 release 构建；不进行交叉编译。macOS 和 Linux 还需要 Python 3，macOS 使用系统的 `sips`、`iconutil` 和 `ditto`。

```sh
# macOS / Linux
./scripts/package-unix.sh
```

```powershell
# Windows PowerShell，使用 Windows Rust 工具链
.\scripts\package-windows.ps1
```

产物位于 `build/packages/`，名称包含版本、平台和 Rust 目标架构：Windows 为包含 `.exe` 的 ZIP，macOS 为包含 `.app` 的 ZIP，Linux 为包含可执行文件和桌面入口资源的 tar.gz。解压后 Windows 可直接运行 `.exe`，macOS 可打开 `.app`，Linux 可运行 `bin/nya-scraping`；如需 Linux 桌面菜单入口，可将包内 `bin` 和 `share` 的内容安装到 `~/.local/bin` 和 `~/.local/share`，并确保 `~/.local/bin` 在 PATH 中。

这些包不包含 GDB、OpenOCD、pyOCD 或 probe-rs，需要按实际使用的后端另行安装。Linux 包依赖目标系统的图形及其他动态运行库；Windows 可能需要对应的 Microsoft Visual C++ 运行库。macOS 包未经签名或公证，分发给其他用户前需自行完成签名和公证。

开发构建已开启优化并保留调试信息，软件渲染器使用更高优化级别，以减少高分屏上的重绘卡顿。首次重新构建依赖会花更长时间。源码与符号报告使用横向滚动，不随窗口宽度重新折行；文件树只在展开或折叠时更新结构，选择变量保留列表模型和滚动位置。固件文件树构建与报告格式化在后台线程完成。

源码页的标签栏记录当前打开的文件，可切换或关闭标签；重复打开同一路径会复用标签。文件树中的源码路径来自编译信息，双击时需要该路径在本机可读取，否则状态栏会显示错误。

源码工作台可点击「浏览…」通过系统文件选择窗口打开源码，也可输入文件绝对路径后点击「打开源码」或回车，通过 `nya-text-backend` 读取文本、编码与换行信息。文本后端支持 UTF-8、UTF-16LE/BE、BOM、常见旧编码、换行归一化与保留编码的保存；也提供 `load_with_encoding` 供调用方显式选择文件编码。工具页扫描 PATH 与 NyaScrapingCore 管理的安装目录；启动时也会扫描一次。硬件操作需要另行安装对应工具和 GDB。

源码页可用 Tree-sitter 进行语法高亮。在「设置 → Tree-sitter 管理」中选择本地 CLI 和可选的 `config.json`，并扫描已配置的语言解析器；也可使用 Cargo 安装 CLI。语言解析器及其高亮查询需要预先按 Tree-sitter 的配置安装。打开源码后在后台生成高亮，无法匹配语言、文件超过 1 MiB 或超过 50000 行时回退到普通文本。高亮视图支持滚动和断点操作；取消「语法高亮」可切回支持文本选择和复制的普通视图。

左侧文件树区域点击「浏览…」可通过系统文件选择窗口打开 AXF、ELF 等编译产物，选中后自动解析；也可输入路径后点击「解析文件」或回车。调试页的「调试文件」也提供「浏览…」，两处共享同一文件路径。文件选择窗口提供常用扩展名筛选和「所有文件」，取消选择保留原路径与解析结果。通过 `nya-firmware-backend` 可查看格式、架构、32/64 位、字节序、入口地址、段、节和普通/动态符号表。支持 ELF（包括常见的 ELF 格式 AXF、OUT、O、SO）、PE/COFF 和单架构 Mach-O；以文件内容识别，与扩展名无关，误写为 `.efl` 也可读取。段地址为虚拟地址，可重定位文件中的地址通常是节内偏移；BSS 单独标识为无文件数据。

包含嵌入式 DWARF 2–5 的文件会显示“目录 → 源文件 → 函数 → 参数/局部变量”文件树，全局/文件静态变量归到声明文件下。默认隐藏函数及其参数/局部变量，可勾选「显示函数」查看；变量行单独显示数据类型。左侧搜索栏按文件完整路径、函数名或链接名即时筛选（不区分大小写），搜索时自动展示匹配函数及其路径，不受「显示函数」开关限制；清空搜索恢复原有展开状态。点击节点展开或折叠，在左侧下方的解析区域查看原始编译路径、声明行列号、函数链接名和地址范围、变量类型、大小、编译期常量及存储位置。类型支持基础类型、typedef、结构/联合/枚举名称、指针、引用、const/volatile 和数组维度。文件树来自调试信息，不要求源码仍在本机；保留 Windows 盘符并统一路径分隔符。支持跨编译单元引用、内联实例、GNU 压缩调试节，以及 DWARF 5 索引地址/字符串和位置列表；ELF 可重定位对象的调试节会应用重定位。

没有可用 DWARF 时从符号表回退提取函数和静态数据符号，放在“无源码位置”分组，类型、参数和源码位置标为未知。缺失、损坏或无法解码的调试信息会显示提示，保留段/节/符号表结果。建议以 `-g` 构建并保留调试信息；优化可能使局部变量的位置不可用。位置表达式和位置列表需要目标栈帧/寄存器才能求值，静态解析本身不读取运行时变量值；连接调试会话并暂停后会求值已添加的监视项。点击左侧变量即可添加到右侧紧凑的名称/类型/值列表，也可手动输入表达式并移除条目；结构体、类和联合体按成员声明顺序保留嵌套层级，点击分支可展开/收起，typedef 与 const/volatile 包装保留原类型名；指针不自动解引用；未连接时值显示为「—」；目标运行时可开启实时刷新查看最近采样值。重复变量按条目身份去重，同名但不同作用域的变量可分别添加。成功重新解析编译产物时会停止采集并清除旧产物的变量监视与波形，保留未解析的手动表达式。输入名称与固件中唯一变量匹配时可自动解析成变量。

解析不依赖 GDB 或探针，不执行输入文件。输入及解压后的 DWARF 各限制 128 MiB；段/节/符号合计、DWARF DIE 数量和源码文件表分别限制 200000 条。段/节/符号报告每类最多预览 1000 条，文件树使用虚拟列表展示。尚不加载外部 PDB、dSYM、DWO/DWP 或补充类型文件，不进行反汇编；裸 BIN、Intel HEX、旧式非 ELF AXF、归档库和通用多架构 Mach-O 不在本次支持范围。

## 项目保存

启动时可新建项目、从历史记录打开项目或浏览 `.nyaproj` 项目文件。点击左上角「保存项目」保存当前固件和源码路径、调试后端及连接参数、监视变量、波形选择和采样设置；首次保存时选择项目文件位置。保存过的项目会出现在下次启动的历史记录中。

点击窗口左下角的状态文字可打开「系统日志」窗口，查看本次运行的应用和采集事件，以及当前 GDB 会话的最近调试输出。应用事件按程序启动后的经过时间显示，最新事件在最上方；最多保留 1000 条、256 KiB，可在窗口中清空；关闭程序后不保存。

打开项目时会重新解析固件并匹配保存的变量；固件缺失、变量无法唯一匹配或所选后端不可用时会显示错误。项目不会保存或自动写入目标变量的实时数值，也不会自动连接目标或启动采集。

## 实时波形

1. 解析与目标上正在运行的固件一致的可执行 ELF/AXF，保留 DWARF 类型和固定内存地址。
2. 右键左侧变量选择「加入实时波形」，或点击右侧监视条目的眼睛图标。两处共用通道状态，重复添加不会增加通道；最多 16 路。移除监视条目也会移除其波形通道。
3. 使用 OpenOCD 时，可启动板卡对应的服务，例如 `openocd -f interface/stlink.cfg -f target/stm32f4x.cfg`（按实际探针和芯片替换配置）。使用 pyOCD / probe-rs 时，先在调试工具页选择后端，再在调试页连接目标，采集直接复用这条连接，不再打开第二个探针或 GDB 客户端。目标的继续/暂停由用户控制；采集器不会自动下载、复位或继续目标。
4. 波形页会根据当前后端自动选择采集源。OpenOCD 需要填写 Tcl 地址（默认 `127.0.0.1:6666`，与 GDB 的 3333 端口不同）；pyOCD / probe-rs 显示「复用当前连接」，无需 Tcl 地址。点击「开始采集」。目标/探针需要支持运行中读取该内存；不支持时显示错误并停止，不会自动暂停 CPU。Tcl 协议与 `read_memory` 参见 [OpenOCD Tcl RPC](https://openocd.org/doc-release/html/Tcl-Scripting-API.html) 和 [内存读取命令](https://openocd.org/doc/html/General-Commands.html)。

在波形图区域右键可导出当前图表的 CSV，或清空当前图表各通道的历史波形；清空后正在进行的采集会继续。CSV 每行包含通道名、作用域、相对本次采集开始的时间（秒）和值，导出的是各通道当前保留的全部原始样本，而非仅可见时间窗口或绘图包络。

采集使用独立线程。相邻/重叠变量合并成块，不跨越未选中的地址间隙。OpenOCD 使用持久 TCP 连接与 TCP_NODELAY，优先对齐 32 位传输，一轮所有块合并成一次 RPC。pyOCD / probe-rs 将批量内存请求送入现有工作线程，通过当前 GDB/MI 连接逐块执行 `-data-read-memory-bytes`，不求值变量、不创建第二个探针会话。采集响应通过有界通道直接回给采集线程，不逐点排入 UI 消息队列。收到响应后立即采集下一轮，没有人为轮询间隔。UI 每 33 ms 获取一次快照，波形页不可见时跳过绘图；每通道预分配 32768 点环形缓冲，按像素桶保留最小/最大值绘图。页面显示实测平均采集轮数/秒、保留点数、缓冲淘汰数和非有限值数。停止后保留现有波形，重新开始会清空缓冲。监视与波形共用一个采集连接，最多 64 个固定地址数值变量，其中波形最多 16 路，已展开的固定地址结构体数值成员也可单独加入波形；仅监视的变量只保留最新值。

支持 DWARF 标明的有/无符号 8/16/32/64 位整数、32/64 位浮点和布尔值，递归解析 typedef 与 const/volatile 修饰并遵循目标字节序。需要栈帧的局部变量、结构体/数组/指针、未知类型、可重定位目标文件和未解析表达式不能打开采集开关。

采集不执行目标端采样代码，也不发送 halt/resume/reset 或内存写入命令；SWD/JTAG 内存读取仍可能与 CPU/DMA 争用总线，不能保证零性能影响。实际采样率取决于探针、时钟、芯片和通道分布，尚未做真实探针的吞吐/性能测量。时间戳为主机读请求起止的中点，同轮通道并非硬件同步采样，64 位值可能跨两次 32 位读取；无法保证捕捉采样间隔之间的所有变化。带数据缓存的芯片可能读到尚未回写的内存视图，采集器不会通过缓存维护干扰目标。数值绘图使用 f64，超过 53 位有效位的整数存在舍入。当前时窗固定为最近 5 秒（受缓冲容量限制）；触发、游标、缩放、导出及 RTT/SWO 采集尚未接入。


pyOCD / probe-rs 采集需要支持 `maintenance set target-non-stop on` 的 GDB。程序启动 pyOCD 时会关闭其内存缓存；外部 pyOCD 服务建议传入 `-O cache.enable_memory=false`，避免暂停时读到缓存值。协议实现参考 [pyOCD GDB 服务](https://pyocd.io/docs/gdbserver.html)、[GDB target-non-stop](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Maintenance-Commands.html) 和 [probe-rs GDB 读取实现](https://github.com/probe-rs/probe-rs/blob/master/probe-rs-tools/src/bin/probe-rs/cmd/gdb_server/target/base.rs)。目前通过模拟后端、真实 GNU GDB 与离屏集成验证，三种后端的真实探针吞吐与目标总线影响仍待硬件验收。

## 调试后端管理

中间「调试工具」页统一管理 OpenOCD、pyOCD 和 probe-rs。「刷新」扫描 PATH 与 NyaScrapingCore 管理的版本，显示版本、可执行文件路径和选择状态。「使用」将该项设为当前后端，顶部同步显示选择；重启后恢复后端及版本。

在「安装后端」中选择工具，输入具体版本后安装；版本留空则安装最新稳定版。安装完成后再点击「使用」切换。安装需要网络；pyOCD 使用 Python venv/pip，probe-rs 使用 cargo，OpenOCD 使用 curl/tar。长任务在工作线程执行，处理期间禁用重复操作；安装时会弹出动态进度窗口，可点击「取消」终止安装并清理未完成的安装目录。OpenOCD 显示下载进度、速度和预计剩余时间；支持机器可读进度的 pip 显示当前依赖文件的下载数据，probe-rs 显示已下载依赖数和 Cargo 编译进度。pip 和 Cargo 不提供整个安装任务的下载总量。详细安装日志输出到启动终端，结果或错误显示在页面和底部状态栏。

已有本地工具可在「添加本地后端」中选择类型、填写名称并选择目录，然后点击「添加」。名称使用字母、数字、点、连字符或下划线；目录须直接包含对应可执行文件，或在其 `bin` / `Scripts` 子目录中包含该文件。添加后在列表中点击「使用」。移除引用不会删除本地文件；移动文件后需重新添加。

「卸载」仅用于受管理版本，不删除 PATH 工具。多个 PATH 路径遵循系统优先级，只能选择首个路径。卸载选中版本后，若 PATH 中有同类工具则回退使用，否则当前后端标记为不可用。版本配置继续由 NyaScrapingCore 管理，后端类型另存于其配置目录内的 `desktop-backend` 文件。

## 调试会话

1. 在「调试工具」中选择可用后端。在「调试」页填写 GDB 路径（默认 `arm-none-eabi-gdb`）、ELF/AXF 文件和端口。点击目标旁的「选择…」可按型号、厂商或配置文件搜索并选择目标，也可手动填写；「刷新」重新读取当前后端支持的目标。pyOCD 使用 `json --targets`，probe-rs 使用 `chip list`；OpenOCD 扫描当前安装的脚本目录及 `OPENOCD_SCRIPTS` 中的 `target/*.cfg`，选中后填入完整路径。OpenOCD 的「Probe」行可搜索并选择 `interface/*.cfg`（包括 `interface/ftdi/` 等子目录），也可点击「浏览…」选择自定义配置或直接填写路径；刷新会同时更新目标与 Probe 配置。选择的是探针接口配置，实际探针由 OpenOCD 根据配置连接。pyOCD/probe-rs 不使用此配置。切换后端类型会清除旧目标和 Probe 配置，连接会话或使用外部服务时禁止修改。也可勾选「连接已有本机 GDB 服务」，直接连接 `127.0.0.1:端口`。
2. 点击「连接」。程序加载符号并连接目标，按 GDB 实际线程状态显示运行或暂停，不自动下载固件。顶部工具栏提供继续、暂停、步过、步入、步出、复位与断开；「下载」仅在暂停时可用，通过 GDB 将当前 ELF/AXF 写入目标。复位使用服务端的 `monitor reset halt`，不支持此命令的服务端会返回错误。
3. 解析带 DWARF 行号信息的编译产物后，源码页行号旁的紫色小圆点提示与机器指令对应的行；缺少行号信息或源码路径不匹配时会显示提示。点击行号旁可添加或移除断点，尚未连接或目标运行时添加的断点以橙色标记，连接后目标暂停时自动提交给 GDB；提交失败会保留待设置断点并显示错误。红色表示已设置的断点，空心表示禁用。顶部菜单「调试 → 断点记录」打开独立窗口，查看、启用、禁用或删除断点；「调试」菜单还提供连接、断开、继续、暂停、单步、复位和下载操作。也可在「调试」页输入函数名或 `文件:行号` 添加断点，点击断点旁的「×」移除。GDB 可能将断点调整到附近可执行的行，源码标记显示实际位置。调用栈点击可选择栈帧；本机存在对应源码时会打开源码，并在源码页显示当前帧位置。优化或缺少源码时仍保留 GDB 返回的帧与地址。待设置断点保存在当前程序会话中，关闭程序后不会恢复。
4. 点击左侧变量或手动添加表达式。暂停、切换栈帧、添加或展开监视项时读取数值与类型；断开或会话异常后清除旧值；继续运行后通过实时刷新更新数值。结构体沿原有成员层级显示数值；文件变量按源码文件限定，局部变量只在所属函数栈帧求值。不可用/已优化变量显示错误，不以 0 代替。

使用 pyOCD 时，目标下方会显示芯片包管理入口。「添加本地 .pack…」通过系统文件选择窗口导入 CMSIS Device Family Pack，先使用当前 pyOCD 验证，再将绝对路径保存在 NyaScrapingCore 配置目录的 `desktop-packs.json` 中；本地文件需保留原位置，重启后仍会加载。目标枚举、启动 GDB 服务及维护命令会自动传入这些 `--pack` 参数。「移除引用」仅移除配置，不删除原文件。输入芯片型号后点击「在线安装芯片包」会调用当前 pyOCD 的 `pack install`，需要网络和可用的 cmsis-pack-manager；完成后自动刷新目标列表。pyOCD 可能在无匹配型号时仍正常退出，应确认目标列表出现所需芯片。芯片包管理仅在断开会话后可用。目标查询最多等待 30 秒，在线安装最多等待 5 分钟；失败原因显示在目标区域与状态栏。功能依据 [pyOCD 官方目标与芯片包说明](https://pyocd.io/docs/target_support.html)。

右侧「实时刷新」与波形共用当前后端的无暂停采集。OpenOCD 检查 Tcl 地址（默认 `127.0.0.1:6666`）；pyOCD / probe-rs 先连接调试会话，界面自动选择当前连接。可选择 100、50、20、10、5、2（默认）、1、0.5、0.2 或 0.1 Hz，也可选择「自定义…」输入 0.1–1000 Hz（支持小数，例如 7.5 Hz），按回车或点击「应用」生效。非法频率会显示错误并关闭刷新。不开波形时也可单独勾选监视刷新；波形已启动时，监视加入同一条连接，保留采集时间基准和已有波形，不重启探针或暂停目标。每轮优先读取波形，仅在监视刷新到期时把监视地址并入批量请求；改变监视频率不会给波形加固定等待间隔。关闭监视刷新后，已有波形继续采集。

运行中无暂停监视支持固定地址的数值标量，以及固定地址结构体中已展开且偏移和类型可确定的数值成员。局部栈变量、位域、数组、指针和未解析表达式需要暂停后通过 GDB 求值，界面会显示原因，不会为了刷新自动暂停 CPU。暂停状态仍可按原来的层级展开与 GDB 求值流程工作。GDB 的周期刷新不会再发送 interrupt/continue，手动参数写入与显式暂停操作仍保留原有行为。pyOCD 使用其原生 non-stop 协议；probe-rs 使用本地 RSP 桥接，将原有全停协议的运行/停止事件转换成 non-stop 通知，同时保留 GDB 的全停调试界面语义。采集只发送内存读取；协议桥接不会为采样发送暂停、继续、复位或写入。正常断点、异常、单步及用户暂停事件仍交给调试会话处理，采样失败不会回退为暂停采集。切换后端或调试连接丢失会停止旧的会话采集，防止旧数据填入新目标。实际读取频率取决于探针和地址分布，高频设置不能保证达到标称值。

右侧监视列表点击数值旁的「✎」，输入新值后按回车或点击「写入」，即可通过 GDB 修改变量或结构体成员并回读结果。支持十进制、浮点、十六进制等 GDB 数值表达式；只读值、不可赋值表达式和作用域不匹配会显示错误。运行中写入会短暂中断目标，确认是本次中断后写入，成功则自动恢复运行；若遇断点、写入/回读失败，目标保持暂停供检查。此方式会影响目标时序，不提供无暂停内存写入。

GDB 必须支持目标架构。会话控制使用异步 MI 事件更新，命令默认 8 秒超时，下载为 60 秒；输出缓冲、调用栈和每次监视求值数量有上限。会话内自动求值禁止调用目标函数。连接失败、异常退出、断开或关闭程序时回收 GDB 与程序启动的服务端；外部服务不由程序终止。连接期间禁止切换/卸载后端和替换固件。目标参数当前仅保存在界面内，TOML 配置导入、调试任务取消、线程选择、寄存器/内存视图尚未接入。

## 验证

```sh
cargo fmt --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings

# 离屏界面/性能及三种后端的共享采集检查（需要本地 TCP 监听权限）
cargo run -p nya-scraping --example ui_perf --locked

# 单独验证 Rust 文本后端：
cargo test -p nya-text-backend --locked
# 单独验证编译产物解析：
cargo test -p nya-firmware-backend --locked
```

直接运行上述验证命令即可。格式检查仅覆盖父 workspace，避免改动独立子模块。根目录 `Cargo.lock` 用于锁定桌面程序依赖，应随代码一起提交。

文本后端测试覆盖 Unicode 路径与正文、UTF-8/UTF-16 往返、旧编码、BOM、混合换行、编码失败保留原文件、文件大小限制，以及 Unix 符号链接与权限。已在 macOS / Apple Silicon 上通过 workspace 测试、桌面构建、格式和 Clippy 检查；验证时保留失效的 ICU `PKG_CONFIG_PATH`，构建成功且程序未链接 Homebrew ICU。调试回归覆盖模拟 MI 进程的控制/断点/栈帧/异常/超时与进程回收，并在有 GDB 和 C 编译器时验证真实 GDB 的符号、断点与表达式；离屏界面检查覆盖按钮状态、运行时值及迟到结果隔离。尚未进行真实探针连接或固件下载验收。

## 子模块开发

```sh
# 查看父仓库固定的版本
git submodule status
# 在子模块内修改、测试并提交后，父仓库再记录新的提交指针
git add backends/NyaScrapingCore
```

调试核心的修复放在子仓库，面向本应用的调试适配放在 `crates/debug-adapter`，文本处理在 `crates/text-backend` 内独立开发。不要直接在构建脚本里拉取调试后端最新分支。

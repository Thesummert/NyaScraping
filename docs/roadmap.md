# 界面设计与实施路线

## 工作台布局

采用深色桌面工作台：顶部为工程和会话操作，左侧为模块导航，中央显示当前任务，底部展示状态。主题颜色集中在 `theme.slint`，容器在 `components/`，功能视图在 `pages/`，Rust 模型映射集中在 `presenter.rs`。

| 页面 | 目标能力 | 当前骨架 |
| --- | --- | --- |
| 源码工作台 | 工程树、源码、断点、当前执行行、调用栈 | 输入路径后读取文本、编码、换行；只读 |
| 变量监视 | 局部变量、表达式、类型、展开、格式切换 | 页面布局与接口 |
| 实时波形 | 多通道、时基、触发、游标、缩放、导出 | 空态网格、有界缓冲模型 |
| 调试工具 | 发现、安装、版本选择、卸载、探针列表 | 可刷新现有工具；版本管理仅有适配接口 |
| 会话控制 | 连接、继续、暂停、单步、复位、断开 | 状态模型；连接按钮禁用 |
| 固件下载 | ELF/HEX/BIN、目标配置、进度、校验 | 烧录适配接口；下载按钮禁用 |

后续加入可调整的面板分隔、内存/寄存器视图和任务日志抽屉。所有空态、忙碌、断开和失败状态需有明确反馈。波形通道同时显示名称、单位与颜色，避免仅依赖颜色区分。

## 实施顺序

1. **骨架验收**：维护 workspace 编译、Rust 原生文本测试和静态检查；后续验证 Linux CI 和实际窗口交互。
2. **会话与目标配置**：实现配置解析、固件选择、探针/板卡设置、连接状态、日志；为长任务加入超时、取消和进程回收。
3. **固件下载与工具管理**：将现有适配接口接入命令/事件；增加任务进度、工具安装/切换/卸载界面与错误提示。首次下载使用实际板卡验证，不在无硬件 CI 自动烧录。
4. **GDB/MI**：接入结构化调试协议，完成暂停/继续/单步、断点、调用栈、局部变量、监视表达式。优先确保异步状态与实际目标一致。
5. **波形采集**：先实现一个可验证的采集源，再完成多通道缓冲、批量刷新、缩放、触发与导出；为 UI 提供明确的有效采样率和丢样信息。
6. **编辑与交付**：Rust 增量文本模型、搜索、字符边界处理与撤销重做；再增加打包、图标、快捷键、布局持久化及 Windows 工具链验证。

## 检查边界

- CI 编译整个 workspace，运行领域测试与 Rust 文本后端的编码、换行和文件保存测试。
- GDB/MI 后续使用录制协议流或假 GDB 进程验证异步事件、错误、超时与退出，不依赖开发者本地的探针。
- 探针连接、下载、擦除、复位、目标采集需在真实硬件上单独验收。
- 当前没有 UI 截图、交互自动化或真实硬件验收，完整调试与采集能力需按上述顺序实现和验证。

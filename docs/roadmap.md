# 界面设计与实施路线

## 工作台布局

采用深色三栏桌面工作台：左侧上方为编译产物文件树，下方为选中项的变量/函数解析；中间通过标签切换源码、波形、段/节/符号和调试工具；右侧常驻已添加的监视变量。顶部中央为继续、暂停、停止、步过、步入、步出和复位工具栏，右侧保留连接与下载，底部展示状态。已接通 GDB/MI 调试会话，按运行/暂停状态启用调试与下载按钮。主题颜色集中在 `theme.slint`，功能视图在 `pages/`，Rust 模型映射集中在 `presenter.rs`。

| 页面 | 目标能力 | 当前骨架 |
| --- | --- | --- |
| 源码工作台 | 工程树、源码、断点、当前执行行、调用栈 | 输入路径后读取文本、编码、换行；只读 |
| 变量监视 | 局部变量、表达式、类型、展开、格式切换 | 从文件树添加变量、手动添加表达式、去重与移除；保留类型和结构体层级；暂停、选帧与展开后读取数值，运行中固定地址数值变量通过共享采集器刷新 |
| 实时波形 | 多通道、时基、触发、游标、缩放、导出 | 右键/开关加入通道、OpenOCD / pyOCD / probe-rs 无暂停采集、16 路波形与 64 路共享监视、5 秒时窗及 min/max 包络 |
| 调试工具 | 发现、安装、版本选择、卸载、探针列表 | 已接通扫描、指定/最新版本安装、后端与版本选择持久化、受管理版本卸载；探针列表待接入 |
| 会话控制 | 连接、继续、暂停、单步、复位、断开 | 支持目标参数、连接、继续/暂停、三种单步、复位、断开及异常回收 |
| 固件下载 | ELF/HEX/BIN、目标配置、进度、校验 | 暂停时通过 GDB 下载当前 ELF/AXF；真实硬件与校验进度待验收 |

后续加入可调整的面板分隔、内存/寄存器视图和任务日志抽屉。所有空态、忙碌、断开和失败状态需有明确反馈。波形通道同时显示名称、单位与颜色，避免仅依赖颜色区分。

## 实施顺序

1. **骨架验收**：维护 workspace 编译、Rust 原生文本测试和静态检查；后续验证 Linux CI 和实际窗口交互。
2. **会话与目标配置**：实现配置解析、固件选择、探针/板卡设置、连接状态、日志；为长任务加入超时、取消和进程回收。
3. **固件下载与工具管理**：将现有适配接口接入命令/事件；工具安装/切换/卸载界面与错误提示已接通；后续增加可取消的任务进度。首次下载使用实际板卡验证，不在无硬件 CI 自动烧录。
4. **GDB/MI**：已接通结构化协议、暂停/继续/单步、断点、调用栈与监视表达式；后续补充线程选择、寄存器/内存视图和更完整的源码交互。
5. **波形采集**：已接入三种后端的共享无暂停监视与波形、多通道有界缓冲、频率设置与实测统计；后续实测硬件吞吐/总线影响，加入可变时基、触发、缩放和导出。
6. **编辑与交付**：Rust 增量文本模型、搜索、字符边界处理与撤销重做；再增加打包、图标、快捷键、布局持久化及 Windows 工具链验证。

## 检查边界

- CI 编译整个 workspace，运行领域测试与 Rust 文本后端的编码、换行和文件保存测试。
- GDB/MI 已使用假 GDB 进程验证异步事件、错误、超时与退出，并在 GDB/cc 可用时执行真实符号与表达式测试，不依赖开发者本地的探针。
- 探针连接、下载、擦除、复位、目标采集需在真实硬件上单独验收。
- 当前没有 UI 截图、交互自动化或真实硬件验收，完整调试与采集能力需按上述顺序实现和验证。
